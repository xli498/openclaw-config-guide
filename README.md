# OpenClaw 配置与排障参考

基于真实部署、故障复盘和运行态验收整理的 OpenClaw 配置参考。它不是官方文档，也不是可以直接覆盖现有实例的配置模板；**先核对当前 OpenClaw 版本与官方 schema，再做最小变更。**

> 适合：已经安装 OpenClaw、需要配置模型/渠道/网络/定时任务，或需要排查运行异常的人。
>
> 不适合：把仓库示例原样复制到生产环境，或在没有备份和回滚点的情况下修改配置。

## 30 秒快速启动

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
openclaw setup
openclaw status
```

然后只配置当前任务需要的 provider、channel 或 skill 字段。字段名、可选值和版本兼容性以**当前安装版本的官方文档与 schema**为准。

## 配置变更闭环

1. **只读核对**：确认当前 OpenClaw 版本、运行态、正式配置路径和目标字段。
2. **保存回滚点**：备份原配置；记录修改前的关键状态。
3. **最小修改**：优先使用官方配置接口或局部 patch，不覆盖整份配置。
4. **最小验证**：先做语法/配置校验，再做一次真实但低风险的运行验证。
5. **运行态复核**：确认 Gateway、模型、渠道、工具和定时任务实际加载了预期值。
6. **失败回滚**：区分连接错误、权限错误、模型不存在、超时和工具协议错误，不靠猜参数反复试错。

## 重点主题

### 模型与 Provider

先区分当前实际使用的 `provider`、`model`、`baseUrl` 和 fallback，不把一次子代理成功当成主会话已修复。新 Provider 必须经过正式配置回读、`openclaw gateway restart` 后的运行态检查、真实请求和新会话复验。不在仓库提交 API key、完整凭据、私有 endpoint、私有 Prompt 或用户数据。

### 渠道与外部投递

“插件已加载”不等于渠道已启动；需要检查运行态、事件订阅、权限和实际消息投递记录。文件投递至少核验文件存在、非空、格式合理以及服务端接收结果；关键任务还要保留独立目标和幂等记录。

### Cron 与自动化

先查任务列表（含停用项）、运行记录、状态文件和实际推送记录，再判断真实来源。Gateway 重启导致的中断不能直接归因于脚本或模型。失效脚本不得从归档直接挂回生产 cron；需要代码审查、最小本地验证和明确的恢复方案。

### 记忆、Skill 与自进化

记忆写入、固定加载文件、Skill 扫描路径、新会话召回和实际遵循必须分开验收。文件存在或 pending 提案不等于已经生效。只能有明确的唯一写入源；不要叠加多个长期记忆写入链路。

## 安全边界

不绕过受保护配置、审批、验证器或平台安全边界；不通过猜测参数、关闭保护或替换核心组件来“修复”问题；先使用正式工具、已授权接口和受控工作流。
