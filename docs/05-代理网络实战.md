# 05 — 代理网络实战

## 概述

OpenClaw 需要访问多种外部 API（模型服务、微信服务、图片服务等），在国内网络环境下代理配置是必备项。本文基于实际部署经验，覆盖 Mihomo 代理配置、per-provider proxy 配置踩坑、HTTP Header 编码问题和代理看门狗。

## Mihomo (Clash Meta) 代理配置

### 基础配置

```text
# /etc/mihomo/config.yaml
port: 7890
socks-port: 7891
allow-lan: false
mode: rule
log-level: info

proxies:
  - name: "hk-node"
    type: ss
    server: your-server.example.com
    port: 443
    cipher: aes-256-gcm
    password: "***"

proxy-groups:
  - name: "Proxy"
    type: select
    proxies:
      - hk-node
      - DIRECT
  - name: "Domestic"
    type: select
    proxies:
      - DIRECT

rules:
  # 国内网站直连
  - DOMAIN-SUFFIX,cn,Domestic
  - DOMAIN-SUFFIX,baidu.com,Domestic
  - DOMAIN-SUFFIX,aliyun.com,Domestic
  - DOMAIN-SUFFIX,tencent.com,Domestic
  - GEOIP,CN,Domestic

  # API 走代理
  - DOMAIN-SUFFIX,openai.com,Proxy
  - DOMAIN-SUFFIX,anthropic.com,Proxy
  # 国内模型 API 直连（与 04-代理网络 的 NO_PROXY 原则一致）
  - DOMAIN-SUFFIX,deepseek.com,Domestic
  - DOMAIN-SUFFIX,xiaomimimo.com,Domestic

  # LAN 直连
  - IP-CIDR,192.168.0.0/16,Domestic

  # 默认走代理
  - MATCH,Proxy
```

### OpenClaw 中使用代理

示例中的代理字段应以当前安装版本的官方 schema 为准；不要把下方内容当作可直接覆盖的 `openclaw.yaml`。OpenClaw 的正式配置以当前版本支持的配置格式和路径为准，先用 `openclaw config` 相关只读命令核对后再做最小修改。

## Per-Provider Proxy 配置

### 全局代理 vs 单提供商代理

官方 schema 中，代理配置位于每个 provider 的 `request.proxy` 下，`mode` 取 `"env-proxy"`（读环境变量）或 `"explicit-proxy"`（显式指定）：

```jsonc
{
  "models": {
    "providers": {
      "openai": {
        // ... 其他 provider 字段
        "request": {
          "proxy": {
            "mode": "explicit-proxy",
            // 显式代理 URL，专用于该 provider
            "url": "http://127.0.0.1:7890"
          }
        }
      },
      "deepseek": {
        // 不设置 request.proxy，走全局环境变量或直连
      }
    }
  }
}
```

### env-proxy vs explicit-proxy 踩坑

```jsonc
{
  "models": {
    "providers": {
      "xiaomi": {
        // ... 其他 provider 字段
        "request": {
          // env-proxy 模式：读 HTTP_PROXY/HTTPS_PROXY 环境变量
          "proxy": { "mode": "env-proxy" }
          // 也可改用显式代理：
          // "proxy": { "mode": "explicit-proxy", "url": "http://127.0.0.1:7890" }
        }
      }
    }
  }
}
```

#### 实际问题：某些版本 explicit-proxy 与 Node.js undici 不兼容

> 此为特定版本实战经验，非官方通用结论；两种模式官方均支持。遇到时先升级 OpenClaw 再对照官方文档。

当使用 explicit-proxy 模式时，OpenClaw 内部通过 undici（Node.js 的 HTTP 客户端库）发送请求。在某些版本的 undici 中，代理隧道建立失败，返回：

```
TypeError: fetch failed
    at Object.fetch (node:internal/deps/undici/undici:11576:11)
cause: ConnectTimeoutError: Connect Timeout Error
```

**解决方案**：改用 `env-proxy` 模式并设置环境变量：

```bash
export HTTP_PROXY="http://127.0.0.1:7890"
export HTTPS_PROXY="http://127.0.0.1:7890"
export NO_PROXY="localhost,127.0.0.1,.local"
```

然后在配置中：

```jsonc
{
  "models": {
    "providers": {
      "xiaomi": {
        // ... 其他 provider 字段
        "request": {
          // env-proxy：通过环境变量走代理
          "proxy": { "mode": "env-proxy" }
        }
      }
    }
  }
}
```

## HTTP Header 中文字符问题

### 问题描述

当 OpenClaw 请求中包含自定义 HTTP Header 且值为中文字符时，Node.js HTTP 模块会报错：

```
TypeError: The header content contains invalid characters
    at ServerResponse.setHeader (node:_http_outgoing:653:3)
    at ...
```

### 原因

HTTP/1.1 规范（RFC 7230）要求 Header 值只能包含可见 ASCII 字符（0x21-0x7E）。中文字符的 UTF-8 编码包含高位字节，不符合规范。

### 影响场景

- 自定义 User-Agent 包含中文
- 自定义 Header 包含中文描述
- API 返回的 Header 携带中文（某些国内 API）

### 解决方案

1. **避免中文 Header**：使用英文或拼音代替

2. **URL 编码中文值**：如果必须传递中文，使用 URL 编码
   ```javascript
   headers['X-Custom-Name'] = encodeURIComponent('中文名称');
   ```

3. **Mihomo 层面处理**：在 Mihomo 配置中不对 Header 进行改写
   ```text
   # Mihomo rule: 不做 header 修改
   rules:
     - DOMAIN-SUFFIX,api.example.com,Proxy,no-header-rewrite
   ```

   需要确认 Mihomo 版本是否支持此功能。

## 代理服务守护

使用 systemd、Docker restart policy 或已有 supervisor 管理 Mihomo 生命周期。不要把无限循环的看门狗脚本放入 cron；cron 只能调用一次性、可退出的健康检查。

一次性检查应先确认端口监听，再通过代理请求一个确定的外部地址。重启权限和失败阈值应由服务管理器配置，不要在示例中使用 `pkill` 或无条件重启。

## 验证代理是否生效

```bash
# 测试全局代理
curl -x http://127.0.0.1:7890 https://api.openai.com/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY" | head -100

# 测试特定 provider
# 在 OpenClaw 中发起请求后检查日志：
tail -f /var/log/openclaw/current.log | grep -i proxy
```

## 常见问题

### Q: 代理配置后模型请求仍然超时？

1. 检查代理服务是否运行：`ss -tln | grep 7890`
2. 测试代理连通性：`curl -x http://127.0.0.1:7890 https://www.google.com`
3. 检查 Mihomo rules 是否匹配：查看 Mihomo 日志

### Q: 如何让国内 API 走直连、国外走代理？

在 Mihomo rules 中配置路由：

```text
rules:
  - DOMAIN-SUFFIX,deepseek.com,Domestic    # 国内
  - DOMAIN-SUFFIX,aliyun.com,Domestic      # 国内
  - DOMAIN-SUFFIX,openai.com,Proxy         # 国外
  - GEOIP,CN,Domestic                      # 按 IP 地理位置
  - MATCH,Proxy                            # 默认
```

### Q: env-proxy 和 explicit-proxy 该选哪种？

当前官方 schema 的代理开关是 provider 的 `request.proxy.mode`（`"env-proxy"` 读环境变量 / `"explicit-proxy"` 显式指定），见上文 [Per-Provider Proxy 配置](#per-provider-proxy-配置)。两种模式官方均支持；遇到不兼容优先升级运行时版本，再参考 11-踩坑实录 坑 1 的排查过程。
