# 06 - 记忆与进化

> *"一个不记得过去的 AI，注定会重复犯同样的错误。就像一个每次重启都失忆的金鱼。"*

---

## 为什么记忆系统是核心？

普通 AI 每次对话都是从零开始：
- 不知道你叫什么名字
- 不记得上次聊了什么
- 同一个错误会犯 100 次

不同安装的记忆实现可能不同；本章介绍的是治理模型，不承诺某个插件、目录或脚本在所有版本中存在。先确认当前运行时已经加载的记忆组件，再决定是否增加能力。

---

## 三层记忆架构

```
┌─────────────────────────────────────────┐
│  L3: Models（可执行知识）                │
│  - Skills / 核心规则 / 行为模式          │
│  - 位置: skills/ + CORE_RULES.md         │
├─────────────────────────────────────────┤
│  L2: Patterns（结构化记忆）              │
│  - 教训 / 偏好 / 配置知识               │
│  - 位置: MEMORY.md + memory/topics/      │
├─────────────────────────────────────────┤
│  L1: Traces（日常记录）                  │
│  - 每日对话摘要 / 事件日志              │
│  - 位置: memory/YYYY-MM-DD.md           │
└─────────────────────────────────────────┘
```

### L1: 日常记录

每天自动创建一个文件：

```markdown
# 2026-06-01

## 事件
- 10:00 用户询问如何配置代理
- 14:00 修复了 MiMo degenerate loop 问题
- 16:00 安装了新的学术研究 Skill

## 学到的
- per-provider proxy 必须用 env-proxy
- HTTP Header 不能用中文
```

### L2: 结构化记忆

MEMORY.md 作为索引，详细内容按主题拆分：

```markdown
# MEMORY.md

## reference — 技术参考
- `tools` (29行) — memory/topics/tools.md
- `network` (24行) — memory/topics/network.md

## feedback — 教训经验
- `lessons` (13行) — memory/topics/lessons.md

## user — 用户偏好
- `user-preferences` (16行) — memory/topics/user-preferences.md
```

每个主题文件带元数据标签：

```markdown
# 代理配置

<!-- @category: reference @created: 2026-06-01 @updated: 2026-06-01 -->
@confidence: 0.9
@source: 实战验证

per-provider proxy 必须用 env-proxy，不能用 explicit-proxy...
```

### L3: 可执行知识

Skills 和核心规则，AI 可以直接调用执行。

## 自动记忆、巡检与整理：三个独立职责

本仓库不提供 `auto_memory.py`、`kairos_heartbeat.py` 或 `autodream.py` 等可执行脚本；以下描述的是设计原则，不是复制即用的命令。

### 自动记忆

对话结束后，候选信息应经过价值判断：用户偏好、明确决策、可复用教训和稳定技术事实通常值得保留；一次性任务细节、密钥和无证据推测不应进入长期记忆。

### 状态巡检

巡检可以检查待办、环境健康、失败日志或机会窗口，但应保持低噪声。高置信度且需要用户动作时才提醒；同一目标只保留一个调度源。

### 记忆整理

整理应当是有门槛的后台维护，而不是每次会话强制运行。常见门槛包括：距上次整理的时间、待整理信息量、重复/冲突程度和摘要质量。整理后应能回答：哪些事实被合并、哪些被标为过时、原始证据在哪里。

**共同纪律**：
- 长期记忆只保留有来源、可复用、可核验的信息；
- 一个运行时只保留一个主记忆写入源；
- 自动化必须有日志、停止方式、失败通知和回滚说明；
- 不要用“频率”代替“价值”，低价值自动整理会污染记忆。

## 配置记忆系统（示意）

下面的配置片段仅用于说明插件槽位关系。字段、插件名和配置位置必须以当前版本 schema 为准；安装插件、改配置或重启 Gateway 前先备份并确认影响。

### memory-core 插件（示意）

```jsonc
{
  "plugins": {
    "entries": {
      "memory-core": {
        "enabled": true,
        "config": {
          "dreaming": {
            "enabled": true
          }
        }
      }
    },
    "slots": {
      "memory": "memory-core"
    }
  }
}
```

### lossless-claw（对话精确召回）

```jsonc
{
  "plugins": {
    "entries": {
      "lossless-claw": {
        "enabled": true
      }
    },
    "slots": {
      "contextEngine": "lossless-claw"
    }
  }
}
```

### active-memory（主动记忆）

```jsonc
{
  "plugins": {
    "entries": {
      "active-memory": {
        "enabled": true,
        "config": {
          "agents": ["main"],
          "allowedChatTypes": ["direct"],
          "queryMode": "recent",
          "promptStyle": "balanced",
          "timeoutMs": 15000,
          "maxSummaryChars": 220
        }
      }
    }
  }
}
```

## 实战建议

### 第一天
1. 确保 `memory-core` 插件已启用
2. 创建 `memory/` 目录
3. 开始对话，让 AI 自动积累记忆

### 第一周
1. 检查 `MEMORY.md` 是否在正确记录
2. 如果 AI 重复犯错，手动添加教训到 `memory/topics/lessons.md`
3. 调整 AutoMemory 的触发频率

### 长期
1. 定期检查记忆健康状态
2. 过时的记忆要及时清理
3. 重要的教训要提升到 `AGENTS.md`（L3 级别）
