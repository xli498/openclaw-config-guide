# 06 - 记忆与进化

> *"一个不记得过去的 AI，注定会重复犯同样的错误。就像一个每次重启都失忆的金鱼。"*

---

## 为什么记忆系统是核心？

普通 AI 每次对话都是从零开始：
- 不知道你叫什么名字
- 不记得上次聊了什么
- 同一个错误会犯 100 次

OpenClaw 的记忆系统解决了这个问题。

---

## 三层记忆架构

```
┌─────────────────────────────────────────┐
│  L3: Models（可执行知识）                │
│  - Skills / 核心规则 / 行为模式          │
│  - 位置: skills/ + CORE_RULES.md         │
├─────────────────────────────────────────┤
│  L2: Patterns（结构化记忆）              │
│  - 教训 / 偏好 / 配置知识               │
│  - 位置: MEMORY.md + memory/topics/      │
├─────────────────────────────────────────┤
│  L1: Traces（日常记录）                  │
│  - 每日对话摘要 / 事件日志              │
│  - 位置: memory/YYYY-MM-DD.md           │
└─────────────────────────────────────────┘
```

### L1: 日常记录

每天自动创建一个文件：

```markdown
# 2026-06-01

## 事件
- 10:00 用户询问如何配置代理
- 14:00 修复了 MiMo degenerate loop 问题
- 16:00 安装了新的学术研究 Skill

## 学到的
- per-provider proxy 必须用 env-proxy
- HTTP Header 不能用中文
```

### L2: 结构化记忆

MEMORY.md 作为索引，详细内容按主题拆分：

```markdown
# MEMORY.md

## reference — 技术参考
- `tools` (29行) — memory/topics/tools.md
- `network` (24行) — memory/topics/network.md

## feedback — 教训经验
- `lessons` (13行) — memory/topics/lessons.md

## user — 用户偏好
- `user-preferences` (16行) — memory/topics/user-preferences.md
```

每个主题文件带元数据标签：

```markdown
# 代理配置

<!-- @category: reference @created: 2026-06-01 @updated: 2026-06-01 -->
@confidence: 0.9
@source: 实战验证

per-provider proxy 必须用 env-proxy，不能用 explicit-proxy...
```

### L3: 可执行知识

Skills 和核心规则，AI 可以直接调用执行。

## 自动记忆系统（AutoMemory）

对话结束时自动提取要点：

```jsonc
// scripts/auto_memory.py 的工作流程
1. 对话结束时触发
2. 分析对话内容，提取值得保存的要点
3. 分类为 4 类之一：
   - user: 用户偏好、习惯
   - project: 项目规则、架构决策
   - reference: 技术参考、工具用法
   - feedback: 教训、失败经验
4. 写入对应的记忆文件
```

**写入纪律**：
- 深度对话才触发，短对话不污染记忆
- MEMORY.md ≤ 200 行，超过时自动压缩
- 可推导的事实不持久化

## KAIROS 心跳

每次会话启动时自动扫描环境：

```bash
python3 scripts/kairos_heartbeat.py --quick
```

检测内容：
- 时间上下文（现在几点，用户可能在做什么）
- 待处理任务（有没有到期的提醒）
- 环境健康（代理是否正常，API 是否可用）
- 机会窗口（有没有值得主动处理的事项）

**决策原则**：高置信度（≥0.7）时才建议行动，不主动打扰用户。

## AutoDream 记忆整理

空闲时自动压缩、巩固记忆：

```bash
python3 scripts/autodream.py --check
```

三重门控（至少 2/3 通过才执行）：

| 门控 | 条件 | 说明 |
|:-----|:-----|:-----|
| 时间 | 距上次整理 ≥12 小时 | 避免过于频繁 |
| 量级 | 新增记忆 ≥5 条 | 太少不值得整理 |
| 质量 | 碎片化指数 >0.3 | 太整齐不需要整理 |

整理后的健康评分：
- 新鲜度（记忆是否过时）
- 整理债务（有多少待整理的内容）
- 记忆体量（是否太大需要压缩）
- 覆盖率（是否遗漏重要信息）

## 配置记忆系统

### memory-core 插件

```jsonc
{
  "plugins": {
    "entries": {
      "memory-core": {
        "enabled": true,
        "config": {
          "dreaming": {
            "enabled": true
          }
        }
      }
    },
    "slots": {
      "memory": "memory-core"
    }
  }
}
```

### lossless-claw（对话精确召回）

```jsonc
{
  "plugins": {
    "entries": {
      "lossless-claw": {
        "enabled": true
      }
    },
    "slots": {
      "contextEngine": "lossless-claw"
    }
  }
}
```

### active-memory（主动记忆）

```jsonc
{
  "plugins": {
    "entries": {
      "active-memory": {
        "enabled": true,
        "config": {
          "agents": ["main"],
          "allowedChatTypes": ["direct"],
          "queryMode": "recent",
          "promptStyle": "balanced",
          "timeoutMs": 15000,
          "maxSummaryChars": 220
        }
      }
    }
  }
}
```

## 实战建议

### 第一天
1. 确保 `memory-core` 插件已启用
2. 创建 `memory/` 目录
3. 开始对话，让 AI 自动积累记忆

### 第一周
1. 检查 `MEMORY.md` 是否在正确记录
2. 如果 AI 重复犯错，手动添加教训到 `memory/topics/lessons.md`
3. 调整 AutoMemory 的触发频率

### 长期
1. 定期检查记忆健康状态
2. 过时的记忆要及时清理
3. 重要的教训要提升到 `AGENTS.md`（L3 级别）
