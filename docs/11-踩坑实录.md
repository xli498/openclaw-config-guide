> *"失败不是成功之母，记录失败才是。"*

## 坑 1：代理配置踩坑

### 问题
在 OpenRouter provider 上加 `request.proxy.mode: "explicit-proxy"`，死活连不上。

### 症状
```
Connection error
```

### 根因
OpenClaw 的 `explicit-proxy` 模式与 Node.js undici 不兼容，无法正确建立 CONNECT 隧道。

### 解决
用 `env-proxy` 模式 + 环境变量：

```jsonc
{
  "models": {
    "providers": {
      "openrouter": {
        "request": {
          "proxy": {
            // env-proxy：走 HTTP_PROXY/HTTPS_PROXY 环境变量
            "mode": "env-proxy"
          }
        }
      }
    }
  }
}
```

```bash
# 环境变量
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
```

### 教训
> 该版本实战中 per-provider proxy 用 `env-proxy` 可用；`explicit-proxy` 官方同样支持，遇到不兼容先升级 OpenClaw 再核对官方文档。

## 坑 2：HTTP Header 中文字符

### 问题
OpenRouter provider 的 `X-Title: 小艺 Claw` 含中文字符，走代理后报错。

### 症状
```
ByteString 转换错误（字符 0x5C0F > 255）
```

### 根因
HTTP Header 只支持 ASCII（0-255）。直连时可能做了宽松处理，走 explicit-proxy 后严格校验。

### 解决
```jsonc
{
  "models": {
    "providers": {
      "openrouter": {
        "headers": {
          // Header 值必须纯 ASCII
          "X-Title": "XiaoYi-Claw"
        }
      }
    }
  }
}
```

### 教训
> HTTP Header 值**必须**是纯 ASCII。走代理和直连的 HTTP 客户端行为可能不同。

## 坑 3：测试时改配置导致系统挂掉

### 问题
测试 OpenRouter + Claude 时，修改了 gateway config / proxy / 主模型配置，系统崩溃。

### 根因
测试外部模型连通性时动了不该动的配置。

### 正确做法
```bash
# ✅ 正确：用 curl 测试 API 连通性
curl -x http://127.0.0.1:7890 \
  -H "Authorization: Bearer your-key" \
  https://openrouter.ai/api/v1/models

# ❌ 错误：改 gateway config 来测试
```

### 教训
> **测试 ≠ 配置。** 连通性测试和配置变更是两件事，不能混在一起做。

## 坑 4：MiMo Degenerate Loop

### 问题
MiMo 模型连续输出完全相同文本 8 次，持续 6 分钟。

### 根因
模型层面的问题，不是代码 bug。

### 检测条件
- 连续 3+ 次输出完全相同文本
- 同一个 tool 连续调用 3+ 次且参数完全相同

### 恢复策略
1. 立即停止当前任务
2. 发送新消息打断循环
3. 换一种方法继续

### 预防
在 `AGENTS.md` 中添加检测规则（参见 [12-配置模板.md](./12-配置模板.md)）。

## 坑 5：Skills 默认调用问题

### 问题
用户发论文让我写开题报告，我没调用相关 skills，手搓了一版。

### 用户反应
"你装了 123 个 skills，写开题报告不会调用 academic-research-assistant？"

### 根因
收到任务时没有第一步扫描 available_skills。

### 教训
> 收到任务时，**第一步必须扫描 available_skills** 并调用所有相关 skills。不要问用户要不要用，直接用。

## 坑 6：抖音 DOM 解析失败

### 问题
用 `el.innerText` 查找「私信」按钮，返回空。

### 根因
抖音 React 把私信面板文本全藏在隐藏 DOM 中。

### 解决
```javascript
// ❌ 错误
el.innerText  // 返回空

// ✅ 正确
el.textContent  // 返回所有文本包括隐藏元素
```

### 教训
> React SPA 查找元素：`textContent` > `innerText`

## 坑 7：Compaction 配置

### 问题
DeepSeek V4 模型 token 使用异常偏高。

### 根因
`reserveTokens: 120000` 预留了太多 token，导致 compaction 过早触发。

### 解决
改为 auto-detect from model：
```jsonc
{
  "agents": {
    "defaults": {
      "compaction": {
        "mode": "safeguard",
        "recentTurnsPreserve": 2,
        "keepRecentTokens": 40000
      }
    }
  }
}
```

### 教训
> 不能只靠降低概率，必须做到让它不出现。多层防护：API 参数 + maxTokens 限制 + contextWindow 压缩。

## 通用教训总结

| 教训 | 规则 |
|:-----|:-----|
| 已知可行的方法不做就是偷懒 | 第一次失败后别放弃，换已知能用的工具重试 |
| 测试 ≠ 配置 | 连通性测试不要动 gateway config |
| 不要把选择题抛给用户 | 该用 skill 就直接用，不要问"要不要用" |
| 问两次算失败 | 第一次是发现需求，第二次起必须自动完成 |
| Header 必须 ASCII | 走代理时限制更严格 |
| proxy 用 env-proxy | explicit-proxy 跟 undici 不兼容 |
