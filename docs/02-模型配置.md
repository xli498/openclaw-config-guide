# 02 - 模型配置

> *"选择正确的模型，就像选择正确的火箭引擎。太大浪费燃料，太小飞不出大气层。"*

---

## 使用边界

本章的 provider 名、模型 ID、上下文窗口、价格和字段示例都具有时效性。把它们视为结构说明，不要整段覆盖现有配置；最终以当前官方 schema、provider 文档和本机运行时状态为准。

每次模型改动遵循：**备份 → 最小 patch → 最小调用验证 → 检查会话实际模型 → 必要时回滚**。显式 `/model` 选择可能形成会话级 override，导致渠道/全局路由看起来“没生效”；排查时先检查该会话实际模型与 override 状态。

## 核心概念

OpenClaw 支持同时配置多个模型提供商，通过 `primary` + `fallbacks` 实现自动故障转移。

```
用户消息 → primary 模型处理
              ↓ 失败？
         fallback 1 尝试
              ↓ 失败？
         fallback 2 尝试
              ↓ 全部失败？
         返回错误
```

## DeepSeek（推荐 — 性价比之王）

### 选择 DeepSeek 时的核对项
- 价格以实际 Provider 计费页或账户账单为准，不在本指南固化单价。
- 延迟受区域、代理、负载和模型版本影响，必须用自己的环境实测。
- 能力、上下文窗口和最大输出以当前官方资料、Provider 返回的模型元数据和本机配置为准。

> **重要（2026-07-24 起）**：旧模型 ID `deepseek-chat` / `deepseek-reasoner` 已被 DeepSeek 官方停用，现仅可用 `deepseek-v4-flash` / `deepseek-v4-pro`。上面 cost 字段为峰值价（USD/百万 tokens），以官方定价页为准。若配置不生效，先安装官方 provider 插件：`openclaw plugins install @openclaw/deepseek-provider`。

### 配置

```jsonc
{
  "models": {
    "providers": {
      "deepseek": {
        "timeoutSeconds": 300,
        "baseUrl": "https://api.deepseek.com",
        "api": "openai-completions",
        "apiKey": "sk-your-key",
        "models": [
          {
            "id": "deepseek-v4-flash",
            "name": "DeepSeek V4 Flash",
            "contextWindow": 1000000,
            "maxTokens": 384000,
            "input": ["text"],
            "cost": {
              "input": 0.44,
              "output": 1.32
            }
          },
          {
            "id": "deepseek-v4-pro",
            "name": "DeepSeek V4 Pro",
            "reasoning": true,
            "contextWindow": 1000000,
            "maxTokens": 384000,
            "input": ["text"],
            "cost": {
              "input": 1.32,
              "output": 3.96
            }
          }
        ]
      }
    }
  }
}
```

### 模型选择建议

| 模型 | 适合场景 | 成本 |
|:-----|:---------|:-----|
| `deepseek-v4-flash` | 日常对话（示例；先核对当前模型 ID 和能力） | 以实际账单为准 |
| `deepseek-v4-pro` | 复杂推理（示例；先核对当前模型 ID 和能力） | 以实际账单为准 |

## OpenRouter（海外模型的入口）

### 为什么用 OpenRouter？
- **一个 Key 用所有模型**：Claude、GPT-4o、Gemini、Llama...
- **按用量付费**：不用每个平台都充值
- **适合偶尔需要强模型的场景**

### 配置

```jsonc
{
  "models": {
    "providers": {
      "openrouter": {
        "timeoutSeconds": 300,
        "baseUrl": "https://openrouter.ai/api/v1",
        "api": "openai-completions",
        "apiKey": "sk-or-your-key",
        "request": {
          "proxy": {
            "mode": "env-proxy"
          }
        },
        "headers": {
          // 官方对 openrouter.ai/api/v1 已自动注入 HTTP-Referer/X-OpenRouter-Title，
          // 自定义 Header 仅在使用自定义 baseUrl 时需要
          "X-Title": "YourAppName"
        },
        "models": [
          {
            "id": "anthropic/claude-sonnet-4.6",
            "contextWindow": 1000000,
            "maxTokens": 128000,
            "input": ["text", "image"]
          },
          {
            "id": "openai/gpt-4o",
            "contextWindow": 128000,
            "maxTokens": 16000,
            "input": ["text", "image"]
          }
        ]
      }
    }
  }
}
```

### ⚠️ 重要注意事项

1. **代理问题**：国内服务器必须配置代理才能访问 OpenRouter（详见 [04-代理网络.md](./04-代理网络.md)）
2. **Header 编码**：自定义 Header 值必须是纯 ASCII，中文会导致 ByteString 错误（官方对 openrouter.ai 路由已自动注入合规 Header，通常无需手动设置）
3. **proxy 模式**：该实战版本中 `env-proxy` 验证可用；`explicit-proxy` 官方亦支持，遇到不兼容先升级再核对官方文档
4. **区域限制**：OpenRouter 对部分区域封禁 Claude/GPT 模型（403），需要走代理到美国节点
5. **模型 ID**：OpenRouter 目录中 Claude 系列用点号（如 `anthropic/claude-sonnet-4.6`）；以 `openclaw models list --provider openrouter` 实测为准

## MiMo（小米自研）

### 配置

> 官方 provider id 为 `xiaomi`（按量付费）/ `xiaomi-token-plan`（Token Plan），baseUrl 为 `https://api.xiaomimimo.com/v1`；需先安装官方插件：`openclaw plugins install @openclaw/xiaomi-provider`。

```jsonc
{
  "models": {
    "providers": {
      "xiaomi": {
        "timeoutSeconds": 600,
        "baseUrl": "https://api.xiaomimimo.com/v1",
        "api": "openai-completions",
        "apiKey": "your-mimo-key",
        "models": [
          {
            "id": "mimo-v2.5-pro",
            "reasoning": true,
            "contextWindow": 1048576,
            "maxTokens": 131072,
            "input": ["text"]
          }
        ]
      }
    }
  }
}
```

> 注：`mimo-v2.5-pro` 标称 1M 上下文；部分网关/集成中以模型 ID 后缀 `[1m]`（如 `mimo-v2.5-pro[1m]`）才会启用 1M 上下文，且该变体通常不在 `/models` 列表中返回。接入后以一次真实长上下文请求验证为准，并以小米官方文档为准。

### ⚠️ MiMo 已知问题

MiMo 偶尔会陷入 **Degenerate Loop** —— 连续输出完全相同文本 3+ 次。

**检测方法**：连续 3 次输出完全相同，或同一 tool 连续调用 3+ 次参数相同。

**解决方案**：在 `AGENTS.md` 中添加检测规则：
```markdown
## 模型 Degenerate Loop 检测
- 连续 3+ 次输出完全相同文本 → 立即停止，换思路重试
- 同一 tool 连续调用 3+ 次且参数相同 → 立即停止
```

## 模型别名配置

给模型起个好记的名字：

```jsonc
{
  "agents": {
    "defaults": {
      "models": {
        "deepseek/deepseek-v4-flash": { "alias": "DeepSeek Flash" },
        "deepseek/deepseek-v4-pro": { "alias": "DeepSeek Pro" },
        "openrouter/anthropic/claude-sonnet-4.6": { "alias": "Claude Sonnet" },
        "xiaomi/mimo-v2.5-pro": { "alias": "MiMo" }
      }
    }
  }
}
```

之后就可以用 `/model Claude Sonnet` 快速切换。

## Compaction（上下文压缩）

当对话太长时，OpenClaw 会自动压缩历史。建议配置：

```jsonc
{
  "agents": {
    "defaults": {
      "compaction": {
        "mode": "safeguard",
        "recentTurnsPreserve": 2,
        "keepRecentTokens": 40000
      }
    }
  }
}
```

| 参数 | 含义 | 建议值 |
|:-----|:-----|:------|
| `recentTurnsPreserve` | 保留最近几轮对话 | 2-3（官方默认 3） |
| `keepRecentTokens` | 压缩后至少保留的近期 tokens | 40000（官方默认 20000） |

## 最小变更、验证与回滚

### 最小变更

- 一次只新增或调整一个 provider / model / fallback；
- 不要同时改模型、代理、渠道绑定和 compaction；
- API Key 通过受控配置或环境注入保存，不进入 Git、截图或对话记录；
- 不确定字段时先查当前 schema，不凭旧示例补字段。

### 验证

1. 检查 Gateway 与配置加载状态；
2. 对目标 provider 发起一个极短、无副作用的请求；
3. 查看会话实际生效模型，而不是只看配置文件；
4. 如涉及 fallback，分别验证主模型失败与 fallback 行为，但不要用生产会话做破坏性测试。

### 回滚

- 保留改动前的 provider 与路由片段；
- 连通性失败时先还原刚改的最小字段，不要同时调 token、penalty、超时等参数；
- 会话级模型选择干扰验证时，清除/重置该会话 override 后再测；
- 配置重载或重启前确认当前会话、定时任务和渠道影响。

## 配置示例（需按当前运行态复核）
