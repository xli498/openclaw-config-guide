# 04 - 代理网络

> *"SpaceX 的第一枚火箭在发射台上爆炸了。你的第一次代理配置大概率也会。"*

---

## 为什么需要代理？

如果你在国内服务器上运行 OpenClaw，以下服务需要代理：
- OpenRouter（Claude/GPT 被区域封锁）
- Google Gemini API
- GitHub（偶尔抽风）
- Twitter/X
- YouTube

不需要代理的：
- DeepSeek API（国内直连）
- 小艺渠道（华为国内服务）
- 大部分国内模型

## Mihomo 代理（推荐）

### 安装

```bash
# 下载 Mihomo
wget https://github.com/MetaCubeX/mihomo/releases/latest/download/mihomo-linux-amd64-compatible
chmod +x mihomo-linux-amd64-compatible
mv mihomo-linux-amd64-compatible /usr/local/bin/mihomo
```

### 配置

创建 `~/.config/mihomo/config.yaml`（**这是 Mihomo 配置，不是 OpenClaw 配置**）：

```yaml
mixed-port: 7890
allow-lan: false
mode: rule
log-level: info

proxies:
  - name: "US-Node"
    type: ss
    server: your-server.com
    port: 443
    cipher: chacha20-ietf-poly1305
    password: your-password

proxy-groups:
  - name: "Proxy"
    type: select
    proxies:
      - US-Node
      - DIRECT

  - name: "Gemini"
    type: select
    proxies:
      - US-Node

rules:
  # Gemini 走代理
  - DOMAIN-SUFFIX,google.com,Gemini
  - DOMAIN-SUFFIX,googleapis.com,Gemini
  - DOMAIN-SUFFIX,gemini.google.com,Gemini

  # OpenRouter 走代理
  - DOMAIN-SUFFIX,openrouter.ai,Proxy

  # GitHub 走代理
  - DOMAIN-SUFFIX,github.com,Proxy
  - DOMAIN-SUFFIX,githubusercontent.com,Proxy

  # 国内直连
  - GEOIP,CN,DIRECT
  - MATCH,DIRECT
```

### 启动

```bash
# 前台启动（测试）
mihomo -d ~/.config/mihomo

# 后台启动
setsid mihomo -d ~/.config/mihomo > /tmp/mihomo.log 2>&1 &
```

### 验证

```bash
# 测试代理是否工作
curl -x http://127.0.0.1:7890 https://api.openrouter.ai/api/v1/models

# 测试国内是否直连
curl -x http://127.0.0.1:7890 https://api.deepseek.com/v1/models
```

## OpenClaw 代理配置

### 方式一：环境变量（推荐）

在 `~/.profile` 或 `~/.bashrc` 中添加：

```bash
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
export NO_PROXY=localhost,127.0.0.1,api.deepseek.com
```

然后在 `openclaw.json` 的 `agents.defaults.env` 中也设置：

```jsonc
{
  "agents": {
    "defaults": {
      "env": {
        "HTTP_PROXY": "http://127.0.0.1:7890",
        "HTTPS_PROXY": "http://127.0.0.1:7890",
        "NO_PROXY": "localhost,127.0.0.1,api.deepseek.com"
      }
    }
  }
}
```

### 方式二：Per-Provider 代理

如果只有部分 provider 需要代理：

```jsonc
{
  "models": {
    "providers": {
      "openrouter": {
        "request": {
          "proxy": {
            "mode": "env-proxy"
          }
        }
      }
    }
  }
}
```

### ⚠️ 关键踩坑点

1. **必须用 `env-proxy`，不能用 `explicit-proxy`**
   - OpenClaw 的 `explicit-proxy` 模式与 Node.js undici 不兼容
   - 会报 `Connection error`，怎么配都不通

2. **NO_PROXY 要排除国内 API**
   - 否则 DeepSeek 也会走代理，变慢
   - `api.deepseek.com` 必须在 NO_PROXY 里

3. **Header 编码问题**
   - HTTP Header 只支持 ASCII（0-255）
   - 中文字符（如 `X-Title: 小艺 Claw`）会导致 ByteString 错误
   - 解决：改成英文 `X-Title: XiaoYi-Claw`

## Mihomo 服务守护

将 Mihomo 交给 systemd、Docker restart policy 或现有 supervisor 管理。不要在 shell 中启动无限循环后，再用 cron 重复启动该循环；这会累积多个看门狗和重启竞争。

健康检查应同时确认端口监听和经代理访问一个确定的外部地址。服务重启动作应由服务管理器执行，避免使用 `pkill` 杀掉同机其他 Mihomo 进程。

## SSH 反向隧道（内网穿透）

如果需要从外部访问 OpenClaw（如 QQ Bot 图片服务器），可以用 `localhost.run`：

```bash
# 暴露本地端口 18765
ssh -R 80:localhost:18765 nokey@localhost.run

# 会返回一个公网 URL，如 https://xxxx.lhr.life
```

### 隧道看门狗

隧道可能断开，自动重连脚本：

```bash
#!/bin/bash
while true; do
    ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
        -R 80:localhost:18765 nokey@localhost.run > /tmp/tunnel.log 2>&1
    echo "[$(date)] Tunnel disconnected, reconnecting in 5s..."
    sleep 5
done
```

## 代理切换 SOP

如果代理节点不稳定，需要切换：

```bash
# 1. 查看当前节点
curl -s http://127.0.0.1:9090/proxies | python3 -m json.tool

# 2. 测试节点延迟
curl -x http://127.0.0.1:7890 -w "%{time_total}" -o /dev/null -s https://api.openrouter.ai/api/v1/models

# 3. 切换节点
curl -X PUT -H "Authorization: Bearer your-secret" \
  -d '{"name":"节点名"}' \
  "http://127.0.0.1:9090/proxies/%F0%9F%8E%AF%20Gemini"
```

## 华为云安全组

如果你在华为云服务器上运行 OpenClaw：

- **默认所有外部端口都被拦截**
- 只有 SSH（22）端口通常开放
- 需要在安全组中开放 18789（控制面板）等端口
- 或者使用 SSH 反向隧道代替
