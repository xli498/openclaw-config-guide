## 微信机器人重复回复

### 症状

微信机器人在收到单条消息后，连续回复 2-3 条相同内容。

### 排查过程

1. 检查消息路由：确认消息只被路由到一个 agent
2. 检查并发设置：确认没有多个 agent 实例同时处理
3. 检查 weixin-bridge 日志：
   ```bash
   tail -100 /var/log/openclaw/weixin.log | grep -A5 "duplicate\|repeat"
   ```

### 根因

微信 Bridge 在消息确认时存在竞态条件：Bridge 在收到消息后，向微信服务器发送确认（ACK）和向 agent 转发消息之间的时间窗口内，如果确认超时或重试，可能导致消息被重复投递。

### 解决方案

在渠道配置中增加消息去重：

```jsonc
// 注意：官方 channels 为对象格式（channels.<id>）且未见 deduplicateWindow/deduplicateBy
// 这两个用户级字段（官方 iMessage 等渠道内置 GUID 去重）。以下为私有部署 Bridge 的
// 自定义结构示意，不可直接覆盖现有配置；官方发行版请以当前 schema 为准。
{
  "channels": [
    {
      "id": "wechat",
      "type": "weixin",
      "deduplicateWindow": 5000,
      "deduplicateBy": "messageId"
    }
  ]
}
```

### 验证

```bash
# 发送测试消息后检查日志
tail -f /var/log/openclaw/current.log | grep -E "duplicate|processed.*message"
```

## 插件去重必须重启进程

### 症状

修改插件配置或更新插件文件后，旧版本仍然生效，新配置不生效。

### 排查过程

1. 确认配置文件已保存
2. 使用 `openclaw gateway reload` 重新加载配置
3. 检查日志：旧插件仍在处理请求

### 根因

`openclaw gateway reload` 执行的是热重载，但插件系统对某些类型的变更（特别是插件文件替换和去重逻辑）不支持热重载。插件在加载时被缓存，reload 不会清空插件缓存。

### 解决方案

**必须重启 OpenClaw Gateway 进程**：

```bash
# 标准重启方式
openclaw gateway restart

# 如果标准重启有问题，强制重启
kill -SIGTERM $(pgrep openclaw-gateway)
# 等待进程退出后，服务管理器会自动重启
```

具体可使用：

```bash
python3 -c "
import subprocess, json
# 通过 OpenClaw internal API 触发重启
subprocess.run(['openclaw', 'gateway', 'restart'], check=True)
"
```

**警告**：`openclaw gateway restart` 会导致短暂的服务中断（约 5-10 秒）。

### 最佳实践

1. 更新插件前先通知用户
2. 在低峰期进行插件更新
3. 更新后验证：`openclaw plugins list | grep "version"`

## send_file_to_user JSON 解析 Bug

### 症状

调用 `send_file_to_user` 工具时返回 JSON 解析错误：

```
Error parsing tool result: SyntaxError: Unexpected token ...
column 112-113
```

### 排查过程

检查工具返回内容：

```json
{
  "error": "SyntaxError",
  "message": "Unexpected token '}'\n    at JSON.parse (<anonymous>)",
  "details": "column 112-113"
}
```

检查传入参数：

```json
{
  "fileLocalUrls": ["/path/to/file.pdf"],
  "fileRemoteUrls": ["https://example.com/image.png"]
}
```

### 根因

工具在处理 `fileRemoteUrls` 时，内部分割 URL 列表的逻辑有 bug：在某些版本中，工具的 JSON 序列化在特殊字符（如 URL 中的特殊字符或中文 URL 编码）处失败。

具体问题：
- URL 中包含 `%` 编码的中文字符时，内部 JSON 序列化在第 112-113 列处失败
- 使用 `encodeURIComponent` 后的 URL 被二次编码

### 解决方案

#### 方案 1：只使用 fileLocalUrls

```json
{
  "fileLocalUrls": ["/tmp/document.pdf"]
}
```

先通过 `xiaoyi-file-upload` 将文件上传获取 URL，再作为本地路径传递。

#### 方案 2：对 URL 不进行编码

确保 URL 是纯净的 ASCII 字符串：
```json
{
  "fileRemoteUrls": ["https://cdn.example.com/file/abc123"]
}
```

#### 方案 3：升级版本

该 bug 在 OpenClaw v2.x+ 版本中已修复。检查版本：
```bash
openclaw --version
```

## Compaction 设置问题

### 症状

长对话后上下文窗口耗尽，但自动压缩未触发。

### 排查

检查配置中的 compaction 设置（官方层级为 `agents.defaults.compaction`，常用字段：`enabled` / `mode` / `keepRecentTokens` / `recentTurnsPreserve` / `timeoutSeconds`）：

```jsonc
{
  "agents": {
    "defaults": {
      "compaction": {
        "enabled": true,
        "mode": "safeguard",
        "keepRecentTokens": 20000,
        "recentTurnsPreserve": 3
      }
    }
  }
}
```

### 常见配置错误

1. **keepRecentTokens 过小**：压缩后保留的近期 token 太少，丢失重要上下文（官方默认 20000）

2. **compaction 未启用**：

   错误（空对象，压缩不会生效）：

   ```jsonc
   { "agents": { "defaults": { "compaction": {} } } }
   ```

   正确：

   ```jsonc
   { "agents": { "defaults": { "compaction": { "enabled": true } } } }
   ```

3. **字段层级放错**：compaction 不在根级，而在 `agents.defaults` 下；具体字段以当前版本官方 schema 为准

### 调整建议

```jsonc
// 示例数值需按模型上下文窗口与当前 schema 复核。
{
  "agents": {
    "defaults": {
      "compaction": {
        "enabled": true,
        "mode": "safeguard",
        "keepRecentTokens": 40000,
        "recentTurnsPreserve": 5
      }
    }
  }
}
```

## QQ Bot 链接渲染问题

### 症状

在 QQ Bot 回复中发送 URL，用户看到的是纯文本，不是可点击链接。

### 根因

QQ Bot 的消息渲染机制与微信不同：
- **微信**：自动将 URL 渲染为可点击链接（富文本）
- **QQ Bot**：只将**独立一行的纯 URL**渲染为可点击链接，内联 URL 保持纯文本

### 解决方案

在发送 URL 时，将 URL 放在独立一行：

```markdown
# ❌ 不会渲染为链接
查看详情：https://github.com/xli498/mimo-stable

# ✅ 会渲染为链接
查看详情：

https://github.com/xli498/mimo-stable
```

### 适配脚本

```python
def format_url_for_qq(text: str) -> str:
    """确保 URL 在独立行，以便 QQ Bot 渲染为链接"""
    import re
    url_pattern = r'(https?://[^\s)]+)'

    def replacer(match):
        url = match.group(1)
        # 提取 URL 前的文本
        return f'\n{url}\n'

    result = re.sub(url_pattern, replacer, text)
    # 清理多余空行
    result = re.sub(r'\n{3,}', '\n\n', result)
    return result.strip()
```

## TTS 代理配置

### 场景

微信/QQ 渠道需要语音回复。OpenClaw 内置 `microsoft` TTS provider（基于 `node-edge-tts` 库，使用 Microsoft Edge 在线神经网络 TTS 公共端点），国内访问该端点需要代理。

### OpenClaw 配置（2026-08 核对官方文档）

不需要 `pip install edge-tts`，也不需要自建 TTS HTTP 服务——provider 已内置于 OpenClaw：

```jsonc
{
  "tts": {
    "auto": "always",           // 自动语音：off | always | inbound | tagged
    "provider": "microsoft",
    "providers": {
      "microsoft": {
        "speakerVoice": "zh-CN-XiaoxiaoNeural",
        "lang": "zh-CN"
      }
    }
  }
}
```

说明：

1. 旧版 provider id `edge` 已规范化为 `microsoft`（`openclaw doctor --fix` 会自动重写存量配置）；新配置一律写 `microsoft`
2. 旧版本 OpenClaw 的配置路径在 `messages.tts` 下（如 `messages.tts.providers.microsoft`），升级后以本机 `openclaw doctor` 与官方 schema 为准
3. `speakerVoice` 是规范字段名；各 provider 自身的 `voice`/`voiceId`/`voiceName` 作为旧别名仍可识别

### 代理设置

`microsoft` provider 走 OpenClaw 出站请求的统一代理配置（见 [05-代理网络实战.md](./05-代理网络实战.md)），不要单独为 TTS 配置进程级代理。

### 注意事项

1. Microsoft Edge TTS 公共端点无 SLA/配额承诺，属尽力而为；生产环境建议改用 OpenAI / ElevenLabs（各自需配置 API Key）
2. 会话内可用 `/tts status` 查看当前状态，`/tts audio <文本>` 做一次性验证
3. 并发和限流要求以服务商当前文档为准

### 常驻服务

本仓库不提供未经验证的 TTS Proxy 服务单元。部署前应明确服务来源、运行用户、网络范围、日志脱敏、停止方式与回滚点。

## 总结

| 问题 | 严重性 | 修复难度 | 关键操作 |
|------|--------|----------|---------|
| 微信重复回复 | 中 | 低 | 启用消息去重 |
| 插件去重需重启 | 低 | 低 | `openclaw gateway restart` |
| send_file_to_user bug | 中 | 低 | 只使用 fileLocalUrls |
| Compaction 不触发 | 高 | 低 | 检查 triggerTokens |
| QQ Bot 链接 | 低 | 低 | URL 独立行 |
| TTS 代理 | 低 | 低 | 内置 `microsoft` provider + `request.proxy` |

每遇到一个问题，记录到 `.learnings/ERRORS.md` 中，避免重复踩坑。
