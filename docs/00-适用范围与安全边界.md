# 00 - 适用范围与安全边界

## 这是什么

这是一份基于真实部署经验整理的中文参考指南，不是 OpenClaw 官方配置规范，也不是可直接覆盖现有配置的模板库。

OpenClaw、渠道插件、模型 provider 与第三方服务都可能快速变化。任何字段、命令和成本数据都应先以当前版本的官方 schema 与本机状态为准。

## 使用前先做四件事

1. 运行 `openclaw status`，确认 Gateway 与会话的当前状态。
2. 查看当前配置结构；不要假定配置一定是 YAML 或 JSON，也不要套用其他机器的绝对路径。
3. 每次只做一项最小改动；修改前备份原配置，修改后立即验证。
4. 不要把 API Key、token、cookie、私有 URL 或真实用户数据写进配置示例、截图、Git 提交或记忆文件。

## 风险分级

| 等级 | 典型操作 | 要求 |
|---|---|---|
| 低 | 查看状态、阅读文档、最小连通性检查 | 可直接执行 |
| 中 | 新增 provider、调整模型路由、安装 Skill | 先审查范围与依赖，逐项验证 |
| 高 | 安装插件、修改浏览器/网络权限、重启 Gateway、启用自动化循环 | 先备份，明确影响与回滚方式，再执行 |
| 禁止默认复制 | 关闭沙箱、开放私网访问、粘贴真实密钥、全量覆盖配置 | 仅在隔离环境和明确理由下评估 |

## 本指南的固定写法

每个操作型章节应尽量提供：

- **适用范围**：适配什么版本和场景；
- **最小变更**：只展示需要添加或修改的字段；
- **验证**：如何确认改动生效；
- **回滚**：失败后恢复哪一项；
- **风险**：数据外发、权限扩大或服务中断的条件。

## 安全底线

- 新 Skill 先在临时目录审计，再安装；不要直接 clone 到正式 Skills 目录。
- 安装插件、改配置、重启服务或创建周期自动化前，先确认影响范围。
- 浏览器沙箱与私网访问默认保持受限；“为了能跑”不是关闭保护的理由。
- 配置连通性问题优先做只读检查或最小 API 测试，不要为了测试反复改 Gateway 配置。

## 验证日期

本指南应在每次重大 OpenClaw、渠道或 provider 变更后更新本节的验证日期和兼容性矩阵。未注明验证日期的内容，只能作为历史经验参考。
