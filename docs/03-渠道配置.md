# 03 - 渠道配置

> *"产品再好，用户用不到等于零。渠道就是你的火箭发射台。"*

---

## 使用边界

渠道 SDK、账号权限、审核规则、配置字段和消息限制变化很快。本章示例用于理解配置结构，不保证可直接复制到当前版本。接入渠道会产生真实外部消息、账号风控和隐私影响；先使用测试账号或明确的测试会话。

每次渠道改动只做一个：启用插件、补齐账号信息、调整模型绑定或测试一次收发。不要同时修改渠道、模型、代理和去重策略。

## 渠道概览

OpenClaw 支持多种聊天渠道，让你的 AI 可以通过微信、QQ、Telegram 等工具与你对话。

| 渠道 | 类型 | 难度 | 稳定性 |
|:-----|:-----|:-----|:-------|
| 小艺渠道 | 华为原生 | ⭐ 最简单 | ⭐⭐⭐⭐⭐ |
| 微信 | 网页版登录 | ⭐⭐ 简单 | ⭐⭐⭐ |
| QQ Bot | 官方 API | ⭐⭐⭐ 中等 | ⭐⭐⭐⭐ |
| Telegram | Bot API | ⭐⭐ 简单 | ⭐⭐⭐⭐⭐ |

## 小艺渠道（推荐新手）

### 为什么推荐？
- 华为原生集成，开箱即用
- 不需要额外申请 API
- 支持语音、图片等多模态

### 配置

```jsonc
{
  "channels": {
    "xiaoyi-channel": {
      "wsUrl": "${XIAOYI_WS_URL}",
      "apiKey": "${XIAOYI_API_KEY}",
      "agentId": "your-agent-id",
      "apiId": "your-api-id",
      "uid": "your-uid",
      "enabled": true,
      "fileUploadUrl": "${XIAOYI_FILE_UPLOAD_URL}"
    }
  }
}
```

### 如何获取这些参数？

1. 查阅当前渠道插件对应的官方文档和 schema；
2. 在目标平台创建应用并取得当前版本要求的凭据与标识；
3. 仅通过环境变量、密钥管理器或受保护配置注入凭据；
4. 用低风险测试验证连接，不把生产端点或真实标识写入仓库。

## 微信渠道

### 配置

```jsonc
{
  "channels": {
    "openclaw-weixin": {
      "enabled": true
    }
  },
  "plugins": {
    "entries": {
      "openclaw-weixin": {
        "enabled": true
      }
    }
  }
}
```

### 登录流程

1. 启动 OpenClaw
2. 控制台会显示一个二维码
3. 用微信扫码登录（需要微信网页版权限）
4. 登录成功后自动保持连接

### ⚠️ 注意事项

- 微信网页版可能被封号，建议用小号
- 部分微信账号没有网页版权限
- 连接可能断开，OpenClaw 会自动重连

## QQ Bot 渠道

### 配置

```jsonc
{
  "channels": {
    "qqbot": {
      "appId": "your-app-id",
      "clientSecret": "your-client-secret",
      "enabled": true,
      "model": {
        "primary": "deepseek/deepseek-chat",
        "fallbacks": ["deepseek/deepseek-reasoner"],
        "maxTokens": 64000,
        "timeoutSeconds": 300
      }
    }
  },
  "plugins": {
    "entries": {
      "openclaw-qqbot": {
        "enabled": true
      }
    }
  }
}
```

### 如何获取 QQ Bot 参数？

1. 访问 [QQ 开放平台](https://q.qq.com)
2. 创建机器人应用
3. 获取 App ID 和 Client Secret
4. 配置机器人权限和事件订阅

### TTS（语音消息）

QQ Bot 支持发送语音消息，需要配置 TTS：

```jsonc
{
  "channels": {
    "qqbot": {
      "tts": {
        "provider": "edge-tts",
        "model": "tts-1",
        "voice": "alloy"
      }
    }
  }
}
```

需要安装 `edge-tts`：
```bash
pip install edge-tts
```

### 图片服务器

QQ Bot 发送图片需要一个公网可访问的图片服务器：

```jsonc
{
  "channels": {
    "qqbot": {
      "imageServerBaseUrl": "https://your-image-server.com"
    }
  }
}
```

如果在内网，可以用 SSH 反向隧道：
```bash
ssh -R 80:localhost:18765 nokey@localhost.run
```

## 渠道级模型配置

> 不同版本可能通过渠道绑定或统一路由表配置模型，而非本节展示的嵌套 `model` 字段。先读取当前配置 schema 与实际 session 模型；不要因为旧示例把渠道配置整段覆盖。

每个渠道可以独立配置模型，互不影响：

```jsonc
{
  "channels": {
    "qqbot": {
      "model": {
        "primary": "minimax/MiniMax-M3",
        "fallbacks": ["xiaomimimo/mimo-v2.5-pro", "deepseek/deepseek-chat"]
      }
    },
    "openclaw-weixin": {
      "model": {
        "primary": "minimax/MiniMax-M3",
        "fallbacks": ["xiaomimimo/mimo-v2.5-pro"]
      }
    }
  }
}
```

**用途**：
- QQ Bot 用便宜模型（消息量大）
- 微信用好模型（重要对话）
- 小艺渠道用默认模型

## Bindings（渠道绑定）

Bindings 决定哪个渠道的消息由哪个 Agent 处理：

```jsonc
{
  "bindings": [
    {
      "agentId": "channel-bot",
      "match": { "channel": "qqbot" }
    },
    {
      "agentId": "channel-bot",
      "match": { "channel": "openclaw-weixin" }
    }
  ]
}
```

如果不配置 bindings，所有渠道的消息都由默认 Agent 处理。

## 最小变更、验证与回滚

### 最小变更

- 先在目标渠道启用插件与账号，不夹带模型、代理或 TTS 改动；
- 密钥只放在受控配置中，不进入示例、截图或 Git；
- 图片服务、反向隧道、TTS 代理属于额外网络暴露，必须单独评估和确认；
- 不要用生产用户或群聊作为首次测试对象。

### 验证

1. 检查 Gateway、渠道插件和账号的健康状态；
2. 从测试会话发送一条短文本，确认仅收到一次回复；
3. 检查该渠道实际绑定的 Agent 与模型；
4. 逐项验证图片、语音、主动推送等附加能力，确认外发范围后再启用。

### 回滚

- 记录启用前的渠道配置和账号状态；
- 出现重复回复、权限异常或模型错误时，先停用刚启用的渠道/绑定，保留日志后再排查；
- 不要通过反复重启或同时改多个参数“碰运气”；
- 账号被风控或权限不足时，停止自动重试，先核实平台权限。

## 实战建议

先配**小艺渠道**，零门槛，5 分钟搞定。

三个渠道全开，不同渠道用不同模型，按需分配。
