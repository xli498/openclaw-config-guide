# 03 - 渠道配置

> *"产品再好，用户用不到等于零。渠道就是你的火箭发射台。"*

---

## 使用边界

渠道 SDK、账号权限、审核规则、配置字段和消息限制变化很快。本章示例用于理解配置结构，不保证可直接复制到当前版本。接入渠道会产生真实外部消息、账号风控和隐私影响；先使用测试账号或明确的测试会话。

每次渠道改动只做一个：启用插件、补齐账号信息、调整模型绑定或测试一次收发。不要同时修改渠道、模型、代理和去重策略。

## 渠道概览

OpenClaw 支持多种聊天渠道，让你的 AI 可以通过微信、QQ、Telegram 等工具与你对话。

| 渠道 | 类型 | 难度 | 稳定性 |
|:-----|:-----|:-----|:-------|
| 小艺渠道 | 华为原生 | ⭐ 最简单 | ⭐⭐⭐⭐⭐ |
| 微信 | 网页版登录 | ⭐⭐ 简单 | ⭐⭐⭐ |
| QQ Bot | 官方 API | ⭐⭐⭐ 中等 | ⭐⭐⭐⭐ |
| Telegram | Bot API | ⭐⭐ 简单 | ⭐⭐⭐⭐⭐ |

## 小艺渠道（推荐新手）

### 为什么推荐？
- 华为原生集成，开箱即用
- 不需要额外申请 API
- 支持语音、图片等多模态

### 配置

```jsonc
{
  "channels": {
    "xiaoyi-channel": {
      "wsUrl": "${XIAOYI_WS_URL}",
      "apiKey": "${XIAOYI_API_KEY}",
      "agentId": "your-agent-id",
      "apiId": "your-api-id",
      "uid": "your-uid",
      "enabled": true,
      "fileUploadUrl": "${XIAOYI_FILE_UPLOAD_URL}"
    }
  }
}
```

### 如何获取这些参数？

1. 查阅当前渠道插件对应的官方文档和 schema；
2. 在目标平台创建应用并取得当前版本要求的凭据与标识；
3. 仅通过环境变量、密钥管理器或受保护配置注入凭据；
4. 用低风险测试验证连接，不把生产端点或真实标识写入仓库。

## 微信渠道

官方微信渠道是腾讯微信团队维护的外部插件 `@tencent-weixin/openclaw-weixin`（channel id `openclaw-weixin`，别名 weixin/wechat）。**当前官方插件仅支持私聊，不支持群聊。**

### 配置

```bash
# 1. 安装官方插件
openclaw plugins install "@tencent-weixin/openclaw-weixin"

# 2. 启用插件
openclaw config set plugins.entries.openclaw-weixin.enabled true

# 3. 重启 Gateway
openclaw gateway restart
```

```jsonc
{
  "channels": {
    "openclaw-weixin": {
      "enabled": true
    }
  },
  "plugins": {
    "entries": {
      "openclaw-weixin": {
        "enabled": true
      }
    }
  }
}
```

### 登录流程

以当前版本官方插件文档为准。常见流程为启动后按控制台/控制面板指引完成微信侧授权登录。

### ⚠️ 注意事项

- 官方插件支持私聊与媒体收发；群聊暂不支持
- 下方两条为旧桥接方案时期的实战经验，官方插件流程下不一定适用：
  - 旧网页版桥接方案存在封号风险，建议用小号
  - 部分微信账号没有网页版权限
- 连接可能断开，OpenClaw 会自动重连

## QQ Bot 渠道

### 配置

```jsonc
{
  "channels": {
    "qqbot": {
      "appId": "your-app-id",
      "clientSecret": "your-client-secret",
      "enabled": true,
      "model": {
        "primary": "deepseek/deepseek-v4-flash",
        "fallbacks": ["deepseek/deepseek-v4-pro"],
        "maxTokens": 64000,
        "timeoutSeconds": 300
      }
    }
  },
  "plugins": {
    "entries": {
      "openclaw-qqbot": {
        "enabled": true
      }
    }
  }
}
```

### 如何获取 QQ Bot 参数？

1. 访问 [QQ 开放平台](https://q.qq.com)
2. 创建机器人应用
3. 获取 App ID 和 Client Secret
4. 配置机器人权限和事件订阅

### TTS（语音消息）

QQ Bot 支持发送语音消息。TTS 是全局配置（不挂在 `channels.<id>` 下），OpenClaw 内置 `microsoft` provider（基于 `node-edge-tts`，无需 pip 安装、无需 API Key）：

```jsonc
{
  "tts": {
    "auto": "always",           // off | always | inbound | tagged
    "provider": "microsoft",
    "providers": {
      "microsoft": {
        "speakerVoice": "zh-CN-XiaoxiaoNeural",
        "lang": "zh-CN"
      }
    }
  }
}
```

> 注意（2026-08 核对官方文档）：旧版 provider id `edge` 已规范化为 `microsoft`，`openclaw doctor --fix` 会重写存量配置；旧版本 OpenClaw 的配置路径为 `messages.tts.*`。`tts-1`/`alloy` 是 OpenAI TTS 的模型/音色名，仅在 `provider: "openai"` 时使用。详见 [09-常见问题排错.md](./09-常见问题排错.md) 的 TTS 章节。

### 图片服务器

QQ Bot 发送图片需要一个公网可访问的图片服务器：

```jsonc
{
  "channels": {
    "qqbot": {
      "imageServerBaseUrl": "https://your-image-server.com"
    }
  }
}
```

如果在内网，可以用 SSH 反向隧道：
```bash
ssh -R 80:localhost:18765 nokey@localhost.run
```

## 渠道级模型配置

> 当前版本官方推荐用 `channels.modelByChannel` 统一路由表（按渠道 ID/群 ID/私聊 peer 映射模型；会话已有 `/model` override 时不生效），而非本节展示的嵌套 `model` 字段。先读取当前配置 schema 与实际 session 模型；不要因为旧示例把渠道配置整段覆盖。

每个渠道可以独立配置模型，互不影响（官方现行写法 `modelByChannel`）：

```jsonc
{
  "channels": {
    "modelByChannel": {
      "qqbot": "minimax/MiniMax-M3",
      "openclaw-weixin": "deepseek/deepseek-v4-flash"
    }
  }
}
```

**用途**：
- QQ Bot 用便宜模型（消息量大）
- 微信用好模型（重要对话）
- 小艺渠道用默认模型

## Bindings（渠道绑定）

Bindings 决定哪个渠道的消息由哪个 Agent 处理：

```jsonc
{
  "bindings": [
    {
      "agentId": "channel-bot",
      "match": { "channel": "qqbot" }
    },
    {
      "agentId": "channel-bot",
      "match": { "channel": "openclaw-weixin" }
    }
  ]
}
```

如果不配置 bindings，**且只配置了一个 agent**，所有渠道的消息回退到该 agent 处理；多 agent 场景下无匹配 binding 的消息会 fail closed（不会静默落到某个 agent）。注意 `agents.entries` 的 `default` id 在新版本已 retired，不要依赖它。

## 最小变更、验证与回滚

### 最小变更

- 先在目标渠道启用插件与账号，不夹带模型、代理或 TTS 改动；
- 密钥只放在受控配置中，不进入示例、截图或 Git；
- 图片服务、反向隧道、TTS 代理属于额外网络暴露，必须单独评估和确认；
- 不要用生产用户或群聊作为首次测试对象。

### 验证

1. 检查 Gateway、渠道插件和账号的健康状态；
2. 从测试会话发送一条短文本，确认仅收到一次回复；
3. 检查该渠道实际绑定的 Agent 与模型；
4. 逐项验证图片、语音、主动推送等附加能力，确认外发范围后再启用。

### 回滚

- 记录启用前的渠道配置和账号状态；
- 出现重复回复、权限异常或模型错误时，先停用刚启用的渠道/绑定，保留日志后再排查；
- 不要通过反复重启或同时改多个参数“碰运气”；
- 账号被风控或权限不足时，停止自动重试，先核实平台权限。

## 实战建议

### 新手推荐
先配**小艺渠道**，零门槛，5 分钟搞定。

### 进阶推荐
小艺 + 微信双渠道，日常用小艺，重要对话用微信。

### 重度用户
三个渠道全开，不同渠道用不同模型，按需分配。
